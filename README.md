# Process Checker

Небольшое Windows-приложение на Rust, которое работает в системном трее и отслеживает запуск процессов по имени.

При обнаружении подходящего процесса приложение показывает системное окно Windows `MessageBox`.

## Возможности

- 🔍 Поиск процесса по подстроке имени.
- 🚫 Исключение отдельных процессов из проверки.
- 🔄 Автоматическое отслеживание запуска и завершения процессов.
- ⚠️ Windows MessageBox при обнаружении процесса.
- 🖥️ Работа в системном трее без консольного окна в Release-сборке.
- ❌ Завершение приложения через меню системного трея.
- 🔁 Повторное уведомление после завершения и повторного запуска процесса.
- ⚙️ Простая настройка параметров непосредственно в `main.rs`.

## Как это работает

Приложение каждую секунду получает список запущенных процессов Windows.

Для каждого процесса выполняется проверка:

1. Имя процесса содержит заданную подстроку.
2. Имя процесса не входит в список исключений.

Например, при настройке:

```rust
const PROCESS_SUBSTRING: &str = "agent";

const EXCLUDED_PROCESSES: &[&str] = &[
    "my_agent.exe",
    "test_agent.exe",
];
```

будут обнаружены:

```text
agent.exe
AgentService.exe
my_agent_worker.exe
test-agent.exe
```

но будут проигнорированы:

```text
my_agent.exe
test_agent.exe
```

Поиск выполняется без учёта регистра.

Проект использует:

## Настройка

Основные параметры находятся в начале `src/main.rs`.

### Процесс для поиска

```rust
const PROCESS_SUBSTRING: &str = "agent";
```

Например:

```rust
const PROCESS_SUBSTRING: &str = "postgres";
```

Программа будет искать процессы, содержащие `postgres` в имени.

Например:

```text
postgres.exe
postgres_service.exe
my_postgres_worker.exe
```

### Исключения

Список исключений задаётся здесь:

```rust
const EXCLUDED_PROCESSES: &[&str] = &[
    "my_agent.exe",
    "test_agent.exe",
];
```

Имена сравниваются без учёта регистра.

Например:

```text
AGENT.EXE
agent.exe
Agent.exe
```

считаются одним и тем же именем процесса.

Исключение проверяется по полному имени процесса.

### Интервал проверки

По умолчанию проверка выполняется раз в секунду:

```rust
const CHECK_INTERVAL_SECONDS: u64 = 1;
```

Например, для проверки каждые 5 секунд:

```rust
const CHECK_INTERVAL_SECONDS: u64 = 5;
```

## Работа приложения

После запуска приложение не открывает основное окно.

В системном трее появляется иконка:

```text
🟥
```

Приложение продолжает работать в фоне.

### Если подходящего процесса нет

Никаких действий не происходит.

### Если процесс запускается

Появляется Windows MessageBox:

```text
┌────────────────────────────────────┐
│ Process Checker                    │
├────────────────────────────────────┤
│                                    │
│ Обнаружен процесс:                 │
│                                    │
│ agent.exe                          │
│                                    │
│ Поиск: "agent"                     │
│                                    │
│              [ OK ]                │
└────────────────────────────────────┘
```

После нажатия `OK` приложение продолжает мониторинг.

### Если процесс продолжает работать

Повторное сообщение не появляется.

Программа отслеживает изменение состояния:

```text
Процесс отсутствует
        ↓
Процесс запущен
        ↓
MessageBox
        ↓
Процесс продолжает работать
        ↓
ничего не происходит
```

### После завершения процесса

Если процесс был закрыт:

```text
Процесс работает
        ↓
Процесс завершён
        ↓
ожидание
```

Если затем он запускается снова:

```text
Процесс запущен снова
        ↓
MessageBox
```

Таким образом, уведомление появляется только при переходе:

```text
NOT RUNNING → RUNNING
```

## Системный трей

Для управления приложением используется контекстное меню системного трея.

При нажатии правой кнопкой мыши на иконке:

```text
┌──────────────┐
│ Выход        │
└──────────────┘
```

### Выход

Пункт `Выход`:

1. удаляет иконку из системного трея;
2. завершает event loop;
3. завершает приложение.

## Архитектура

Приложение состоит из двух основных частей.

### Основной поток

Основной поток обслуживает `winit EventLoop` и системный трей:

```text
┌───────────────────────────┐
│       winit EventLoop     │
│                           │
│  ┌─────────────────────┐  │
│  │     System Tray     │  │
│  │                     │  │
│  │       Выход         │  │
│  └─────────────────────┘  │
│             ▲             │
│             │             │
│        AppEvent           │
│             │             │
│  ┌─────────────────────┐  │
│  │     MessageBox      │  │
│  └─────────────────────┘  │
└───────────────────────────┘
```

### Поток мониторинга

Отдельный поток раз в заданный интервал проверяет процессы:

```text
┌───────────────────────────┐
│   Process Monitor Thread  │
│                           │
│       sysinfo             │
│          │                │
│          ▼                │
│   список процессов        │
│          │                │
│          ▼                │
│  поиск PROCESS_SUBSTRING  │
│          │                │
│          ▼                │
│  проверка EXCLUDED_*      │
│          │                │
│          ▼                │
│      AppEvent             │
└───────────┬───────────────┘
            │
            ▼
     EventLoopProxy
            │
            ▼
      Main EventLoop
```

Использование `EventLoopProxy` позволяет передавать события из потока мониторинга в основной event loop.

## Сборка без консольного окна

В начале `main.rs` используется:

```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]
```

Поэтому Debug-сборка может запускаться с консолью, а Release-сборка работает как Windows GUI-приложение без консольного окна.

## Производительность

Проверка выполняется раз в секунду и не требует постоянной загрузки CPU.

Мониторинг выполняется в отдельном потоке, поэтому работа `sysinfo` не блокирует event loop системного трея.

При необходимости интервал можно увеличить:

```rust
const CHECK_INTERVAL_SECONDS: u64 = 5;
```

Чем меньше значение, тем быстрее приложение обнаруживает запуск процесса, но тем чаще выполняется обновление списка процессов.

## Ограничения текущей версии

Текущая версия намеренно сделана простой.

Она:

- ищет только по имени процесса;
- не проверяет полный путь к исполняемому файлу;
- не показывает PID найденного процесса;
- не имеет внешнего конфигурационного файла;
- не имеет GUI для изменения настроек;
- не запускается автоматически вместе с Windows.

## Возможные дальнейшие улучшения

### 1. Показывать PID

Например:

```text
Обнаружен процесс:

Имя: agent.exe
PID: 15432
```

### 2. Показывать полный путь

Например:

```text
Имя: agent.exe
PID: 15432

Путь:
C:\Program Files\MyApplication\agent.exe
```

Это позволит точно определить, какой именно процесс был найден.

### 3. Вынести настройки в конфигурационный файл

Например:

```toml
process_substring = "agent"
check_interval_seconds = 1

excluded_processes = [
    "my_agent.exe",
    "test_agent.exe",
]
```

Тогда для изменения процесса не потребуется пересобирать приложение.

### 4. Добавить несколько поисковых строк

Например:

```text
agent
worker
service
```

И уведомлять при обнаружении любого подходящего процесса.

### 5. Добавить полноценное Windows Toast Notification

Вместо блокирующего `MessageBox` можно использовать обычное уведомление Windows:

```text
┌───────────────────────────────┐
│ Process Checker               │
│                               │
│ Обнаружен процесс agent.exe   │
└───────────────────────────────┘
```

Это позволит приложению продолжать работу без ожидания нажатия `OK`.

### 6. Добавить автозапуск Windows

Приложение можно зарегистрировать в автозагрузке пользователя, чтобы `checker.exe` автоматически запускался после входа в Windows.
